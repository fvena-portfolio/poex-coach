# Fase 3. Comprensión demostrada del producto

**Objetivo:** conseguir que Francisco comprenda y explique el problema antes de diseñar una solución.

**Entrada:** contexto oficial reconstruido y términos relevantes identificados.

**Acciones:**

1. Pedir a Francisco que invoque `$mattpocock-skills:grill-with-docs`.
2. Formular una sola pregunta cada vez.
3. Para cada pregunta, aportar hechos investigados, separar hipótesis y decisiones, recomendar con criterio y esperar la respuesta de Francisco.
4. Comprobar:
   - problema y motivo;
   - usuario, actor o sistema afectado;
   - comportamiento actual y esperado;
   - criterios de aceptación;
   - flujo principal, errores y límites;
   - incógnitas y supuestos;
   - fuera de alcance.
5. Utilizar `$mattpocock-skills:domain-modeling` para términos ambiguos o sobrecargados.
6. Contrastar las respuestas con las fuentes oficiales.
7. Mantener visibles las preguntas que requieran alineación externa.
8. Pedir a Francisco una explicación con sus propias palabras.
9. Corregir una sola laguna o contradicción cada vez.

La explicación del agente no demuestra la comprensión de Francisco.

**Resultado:** comprensión compartida, lenguaje consistente y preguntas materiales identificadas.

**Evidencia:** explicación de Francisco, contraste con las fuentes, términos definidos y supuestos registrados.

**Puerta de salida:**

- `SUPERADO`: Francisco explica correctamente el problema, comportamiento, criterios y límites.
- `REVISAR`: la explicación es incompleta, contradictoria o depende del agente.
- `BLOQUEADO`: falta una aclaración externa imprescindible.
